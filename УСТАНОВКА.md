# ЕИГ v5 — установка и настройка

## Что заливать

Заливается **вся папка целиком** — приложение состоит из многих файлов, а не из одного `index.html`.

```
eig-app/
  index.html
  manifest.webmanifest
  sw.js
  DESIGN.md
  УСТАНОВКА.md
  icon-192.png  icon-512.png  icon-512-maskable.png  apple-touch-icon.png
  css/
    tokens.css      токены Material 3 (светлая/тёмная тема), тип-шкала
    app.css         компоненты
  js/
    store.js        хранилище, id/updatedAt, настройки
    scales.js       шкалы 0–4, индекс, режимы дня
    content.js      все фразы, эмодзи, тексты режимов
    programs.js     упражнения, сессии, план недели, пресеты
    volume.js       тоннаж, недели, уровень дня, иконки
    motivation.js   правила плашки, стрик, рекорды
    rings.js        кольца и график
    picker.js       барабанный пикер
    photos.js       фото (IndexedDB)
    sync.js         снапшот, слияние, WebDAV
    ai.js           разбор недели, пополнение контента
    train.js        подходы, таймеры, APRE, финиш
    history.js      календарь, лог, CSV
    app.js          запуск, вкладки, тема, экран «Сегодня»
```

Скрипты подключаются классическими `<script src>` в фиксированном порядке — сборки нет,
npm-зависимостей нет. Порядок менять нельзя: файлы рассчитывают на глобальные функции предыдущих.

## Установка на телефон (GitHub Pages)

1. Залей содержимое папки `eig-app/eig-app/` в репозиторий (в корень ветки или в `docs/`).
2. Settings → Pages → выбери ветку и папку. Дождись зелёной галочки.
3. Открой выданный адрес в Chrome на телефоне.
4. Меню Chrome → «Установить приложение» (или «Добавить на главный экран»).
5. Приложение запускается офлайн: `sw.js` кэширует все файлы из списка `ASSETS`.

**После обновления файлов** подними версию кэша в `sw.js` (`CACHE = "eig-v5-1"` и так далее).
При следующем заходе внизу появится плашка «Есть обновление · Обновить» — тап по ней
применяет новую версию и перезагружает страницу. Без смены `CACHE` браузер будет отдавать старое.

## Где лежат данные

Всё хранится **только в браузере этого устройства**. Никаких серверов, никакой отправки данных
без явного действия (запрос к ИИ или синхронизация).

| Ключ localStorage | Что внутри |
|---|---|
| `eig_checkins_v1` | утренние чек-ины: индекс, режим, значения шкал, план дня |
| `eig_sessions_v1` | закрытые тренировки: подходы, тоннаж, кардио, рекорды, фото |
| `eig_draft_v3` | незакрытая тренировка сегодняшнего дня (черновик) |
| `eig_settings_v1` | имя, тема, план недели, настройки ИИ и синхронизации |
| `eig_content_v1` | твои правки контента поверх стандартных фраз |
| `eig_motiv_v1` | последние показанные фразы и выбор на сегодня |
| `eig_ai_v1` | история разборов от ИИ |
| `eig_sync_v1` | идентификатор устройства и журнал синхронизаций |

**IndexedDB**, база `eig`, хранилище `photos` — сами фотографии. Они **не входят** в JSON-экспорт:
файл был бы огромным. Фото переносятся между устройствами только через WebDAV-синхронизацию.

Старые данные читаются как есть: чек-ины по шкале 0–10 показываются как «7/10», а на слайдерах
округляются до шкалы 0–4; сессии без поля `log` отображаются по старым полям `weight`/`actual`.

## Раздел «ИИ»

⚙️ → «ИИ». Два провайдера:

**OpenAI-совместимый** — любой сервер с эндпоинтом `/chat/completions`: llama-swap, llama.cpp server,
LM Studio, Ollama с OpenAI-слоем, OpenRouter.

- Base URL: адрес **с** `/v1`, например `http://localhost:8080/v1` или `https://openrouter.ai/api/v1`.
- API-ключ: для локального сервера можно оставить пустым — заголовок `Authorization` тогда не отправляется.
- Модель: имя как его отдаёт сервер.

**Anthropic** — прямой доступ к `https://api.anthropic.com/v1/messages`.

- Base URL не нужен. Ключ обязателен. Модель по умолчанию `claude-opus-5`.
- Запрос уходит с заголовком `anthropic-dangerous-direct-browser-access: true` — иначе браузер
  заблокирует его на CORS.

Кнопка «Проверить» шлёт короткий запрос и показывает ответ или текст ошибки.

**Про CORS.** Приложение — обычная страница, запросы идут из браузера. Локальный сервер должен
отдавать `Access-Control-Allow-Origin` с адресом приложения (для llama-swap/llama.cpp — ключ
`--host 0.0.0.0` и разрешённый origin в конфиге). Если сервер этого не умеет, разбор всё равно
доступен: кнопка «📋 Скопировать для ИИ» кладёт весь запрос в буфер — вставь его в любой чат вручную.

**Ключ никогда не покидает устройство**: он не попадает ни в экспорт JSON, ни в снапшот синхронизации.

## Пресеты недели

Три слота — Lite, Крепыш, IronMan. Это заготовки, а не догма: настрой «Настроить» под себя
(дни, тип программы, дни недели, длительность) и нажми «Сохранить как пресет» — выбери, какой слот
перезаписать, при желании дай своё название. Дальше переключаешься одним тапом.
Кнопка «Вернуть стандартные пресеты» в том же шите откатывает всё к заводским.

## Бюджет времени

Длительность занятия — не подпись, а реальный бюджет. Приложение оценивает продолжительность так:
на каждое упражнение 50 секунд на подход к снаряду и настройку, 40 секунд на рабочий подход
и запланированная пауза между подходами. Из выбранного времени сначала вычитается кардио
(30–35 % бюджета, для интервальных дней меньше), остаток — на силовую часть.

Если план не влезает, он урезается: сначала выкидываются самые низкоприоритетные упражнения
(изоляция раньше базы, кор раньше базовых движений), и только если резать больше нечего —
снимается по подходу, но не ниже двух. Минимум два силовых упражнения остаётся всегда.
Оценка показана на карточке «Тренировка сегодня» и в шапке вкладки «Тренировка»:
«примерно 43 мин (силовая 28 мин + кардио 15 мин)».

## Раздел «Контент»

⚙️ → «Контент». Все фразы, эмодзи и тексты режимов лежат в `js/content.js`, а твои правки — поверх них,
в `eig_content_v1`.

- **Экспорт JSON** — выгружает текущий контент целиком.
- **Импорт JSON** — загружает файл того же формата. Проверяется структура: корень — объект,
  `phrases.<категория>.items` — массив непустых строк. Файл не того формата отклоняется с понятным
  сообщением, данные не меняются.
- **Сбросить** — удаляет твои правки, остаются стандартные фразы.
- **Пополнить через ИИ** — просит модель написать по 10 новых фраз на категорию. Ответ проверяется:
  невалидный JSON или чужая структура → тост с объяснением, контент не трогается. Дубликаты отсеиваются.

Формат файла:

```json
{
  "phrases": {
    "default": { "emoji": ["☀️"], "items": ["Своя фраза на сегодня"] },
    "streak":  { "items": ["{n} дней подряд — так держать"] }
  },
  "setToasts": ["Свой тост после подхода"]
}
```

Плейсхолдеры: `{name}` — имя из настроек (по умолчанию «бро»), `{n}` — длина стрика.
Массивы объединяются со стандартными, дубликаты отбрасываются.

## Раздел «Синхронизация» (экспериментально)

⚙️ → «Синхронизация». Обмен через WebDAV-папку: приложение читает `eig-sync.json`, сливает с локальными
данными, пишет обратно, затем докачивает недостающие фото из `photos/`.

Слияние идёт по записям: побеждает та, у которой `updatedAt` новее. Удаления помечаются полем
`deletedAt` (tombstone) и тоже участвуют в слиянии — удалённая на одном устройстве запись не
воскресает на другом. Тумбстоуны старше 90 дней чистятся физически.

**Сервер обязан отдавать CORS-заголовки**, иначе браузер не пропустит запрос:

- `Access-Control-Allow-Origin` — точный origin приложения (адрес GitHub Pages);
- `Access-Control-Allow-Methods: GET, PUT, OPTIONS`;
- `Access-Control-Allow-Headers: Authorization, Content-Type`;
- `Access-Control-Allow-Credentials: true`, если используется Basic-авторизация.

Nextcloud из коробки этого не отдаёт — ставь перед ним reverse-proxy (nginx/Caddy), который
добавит заголовки и ответит на preflight-запрос `OPTIONS`.

Без сервера работает файловый обмен: вкладка «Лог» → «Данные» → «Экспорт JSON» кладёт снапшот в файл,
«Импорт JSON» сливает его обратно — тем же алгоритмом по `updatedAt`.

## Фото

Кнопка «📷 Фото» есть на вкладке «Тренировка», в деталях дня календаря и в шите завершения.
Можно выбрать несколько снимков сразу. Каждый ужимается до 1280 px по длинной стороне (JPEG, q 0.8),
миниатюра — 240 px (q 0.7); поворот берётся из EXIF.

Хранятся в IndexedDB, привязаны к дате. Тап по миниатюре открывает полноэкранный вьюер:
свайп или стрелки — между фото дня, «Удалить», «Закрыть». В календаре день с фото помечен 📷.

Фото **не входят в JSON-экспорт**. Единственный способ перенести их на другое устройство — WebDAV.

## Что делать, если что-то сломалось

- **Пустой экран.** Открой консоль (Chrome → меню → Дополнительные инструменты → Инструменты разработчика).
  Скорее всего не загрузился один из `js/*.js` — проверь, что залита вся папка целиком.
- **Обновление не приезжает.** Не поднята версия `CACHE` в `sw.js` (сейчас `eig-v5-1`). Как крайняя мера:
  Настройки сайта → «Очистить данные» (потеряются локальные записи — сначала сделай экспорт).
- **ИИ не отвечает.** Почти всегда CORS. Проверь адрес кнопкой «Проверить», иначе пользуйся
  «Скопировать для ИИ».
- **Данные пропали.** Браузер мог очистить хранилище. Регулярно делай «Экспорт JSON» на вкладке «Лог».
